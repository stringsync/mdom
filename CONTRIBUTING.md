# Contributing

Pull requests are welcome. This repository is a mirror: mdom is developed in a
larger private repository and this one is rebuilt from it on every release. So
a pull request is never merged here on GitHub.

## Opening a pull request

1. Fork the repository and branch from `main`.
2. Make your change, with tests, and run `mdom test` and `mdom fix` (see the
   [README](./README.md#development)).
3. Open a pull request against `main` and say what it changes and why.

## What happens to it

A maintainer imports your pull request into the private repository, keeping
you as the author of its commits, and reviews and lands it there. It reaches
this repository with the next release.

Once the release is out, the pull request is closed with a comment linking the
commit that carries your change. Closing it is not a rejection: the credit is
yours, in the history of that commit.

## Generated files

Some files here are generated by the mirror, so an edit to them cannot be
imported as it is: `package.json`, `biome.json`, `tsconfig.base.json`,
`bunfig.toml` and `bun.lock` at the root, and everything under
`packages/core`. When your pull request changes one, a maintainer may carry
the change over by hand to where the file comes from. Say in the pull request
why you changed it, so that can be done faithfully.
